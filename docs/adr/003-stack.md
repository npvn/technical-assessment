# ADR 003: The stack

Status: accepted, 2026-11-10

## What I needed from it

- a database that can refuse an overlapping booking by itself (see ADR 001)
- typed code that a team can keep working on after me, with clear module boundaries
- tests against a real database, because the double booking guarantee can't be proven with mocks
- one command to run it, for a reviewer who has Docker and nothing else

## The picks

## A change I made on the way: Vitest instead of Jest

I planned on Jest (Nest's long-time default). When I set the project up I checked the installed packages first, and NestJS 12 and Kysely 0.29 are both ESM-only. Jest's ESM support still needs an experimental Node flag and a different transform setup. Nest 12's own starter template has moved to Vitest, which runs ESM natively. I followed the framework's main path instead of fighting it, and checked with a throwaway test that Vitest keeps the decorator metadata Nest's dependency injection needs (it does).

## Things I left out on purpose

- **An ORM with entities.** The booking path is two queries and one insert. An entity layer would hide the one SQL statement that matters most.
- **Redis.** Nothing to cache yet and nothing to lock (ADR 001).
- **A message queue.** Notifications are out of scope. When they come in, an outbox table written in the booking transaction is the first step, before any broker.
- **OpenTelemetry tracing in code.** Described in DESIGN.md as the next step. Logs carry a request id, so a request can be followed today.
